# 会议助手后端运行与前后端联调

本文是会议助手 V1 的运行手册。架构决策见
`docs/superpowers/specs/2026-08-21-meeting-assistant-design.md`，前后端共同契约见
`contracts/meeting-assistant/v1/`。

## 1. 数据边界

- PostgreSQL 是会议、confirmed 转录、匿名 speaker 映射与 AI 纪要的事实源。
- 不保存音频；会议采集也不写 `runtime/subtitles/current.srt`。
- `runtime/meetings/recovery/*.jsonl` 只在 PostgreSQL 短暂写失败时保存 confirmed 文本操作，
  目录权限 `0700`、文件权限 `0600`，成功回放后删除。
- partial 只通过 WebSocket 展示，崩溃时允许丢失。

## 2. PostgreSQL 一次性准备

以 `knowledge` 库管理员执行：

```bash
psql knowledge -f scripts/bootstrap-meeting-db.sql
```

脚本等价于以下一次性授权：

```sql
CREATE ROLE voice_realtime_app LOGIN;
CREATE SCHEMA voice_realtime AUTHORIZATION voice_realtime_app;
REVOKE ALL ON SCHEMA voice_realtime FROM PUBLIC;
GRANT CONNECT ON DATABASE knowledge TO voice_realtime_app;
GRANT USAGE, CREATE ON SCHEMA voice_realtime TO voice_realtime_app;
```

运行时角色不需要创建数据库、角色或访问其他 schema。V1 migration 只新增对象；应用回退时旧版本
忽略该 schema。备份和恢复沿用 `knowledge` 库的现有 `pg_dump`/`pg_restore` 流程。

## 3. 配置与启动

```bash
export VR_MEETING_DATABASE_URL='postgresql://voice_realtime_app@/knowledge'
export VR_MEETING_SCHEMA='voice_realtime'
export VR_MEETING_SUMMARY_MODEL='qwen/qwen3.8-27b'
export VR_MEETING_SUMMARY_REASONING='off'
export VR_SUBTITLE_DIARIZATION='true'
# 可选：按会议设置人名、产品名和缩写
export VR_SUBTITLE_CONTEXT='术语：项目代号、参会人姓名、产品名称'
uv run vr-subtitles
uv run vr-ui
```

Qwen3-ASR 1.7B 与 Sortformer 必须预先存在于各自的项目外供应商缓存；默认禁止隐式下载。
如需覆盖默认 cache 路径，只能通过 `VR_SUBTITLE_MODEL_DIR` 与
`VR_SUBTITLE_DIARIZATION_MODEL_PATH` 指向项目外绝对路径。`vr-ui` 启动时在 advisory lock 下执行
migration、回放 journal、将崩溃遗留的 `recording/finalizing` 标为 `interrupted`，再启动纪要 worker。
初始化失败会记录脱敏错误类型，普通助手继续运行；会议 HTTP API 返回 `storage_unavailable`。

`vr-subtitles`、TTS 桥和 LM Studio 进程可以常驻预热。`SubtitleProxy.start()` 只初始化代理并保持
普通字幕 workload paused，不会自动建立普通字幕连接或接收 PCM。

## 4. 运行时仲裁与会议边界

`RuntimeModeCoordinator` 维护四种稳定模式，并与 PCM owner 固定对应：`assistant/assistant`、
`subtitles/subtitles`、`meeting/meeting`、`idle/none`。服务进程常驻不等于 workload 活跃；任意稳定
时刻只允许一个 owner，prepared target 也不接收 PCM。

进入会议采用两阶段顺序：先 `prepare_start()` 创建 meeting record 并准备无 PCM capture，目标 ready 后
进入 owner `none` 屏障，静默并 drain 来源，再同步 `commit_start()`，原子提交
`meeting/meeting/runtime_revision` 并广播，最后才发布 `recording` 事件。目标准备失败时来源不变；
屏障后的失败优先恢复来源，恢复也失败则全停到 `idle/none`。prepared meeting 被 abort 时必须保留
`interrupted/mode_switch_aborted` 记录，不得删除。

用户命令串行且不互相抢占。shutdown 是唯一可以取消在途转换的路径；它会 abort prepared target、
尽力停止全部 workload，并以一次稳定广播收敛到 `idle/none`。会议完成、异常中止或 EOF finalization
超时后也进入 `idle/none`，不会自动恢复普通字幕或语音助手。会议始终不写普通字幕 `current.srt`。

## 5. 独立前端联调

- HTTP 基址：`http://127.0.0.1:8100/api/v1`
- 运行时快照：`http://127.0.0.1:8100/api/runtime`
- 控制 WebSocket：`ws://127.0.0.1:8100/ws/v1/control`
- 助手控制兼容 WebSocket：`ws://127.0.0.1:8100/ws/assistant/cmd`
- 会议事件 WebSocket：`ws://127.0.0.1:8100/ws/v1/meetings`
- 只读字幕 WebSocket：`ws://127.0.0.1:8100/ws/subtitles`
- OpenAPI：`contracts/meeting-assistant/v1/openapi.json`
- AsyncAPI：`contracts/meeting-assistant/v1/asyncapi.yaml`
- JSON Schema 与 fixtures：`contracts/meeting-assistant/v1/schemas/`、`fixtures/`

允许的独立前端 Origin 由 `VR_MEETING_ALLOWED_ORIGINS` 配置，必须是 loopback URL。命令必须携带
`request_id`；普通字幕由 `start_subtitles` 控制命令激活，连接 `/ws/subtitles` 本身不改变或抢占模式。
该只读通道仅在 `subtitles/meeting` 合法；非法建连或存续期失去资格时固定关闭 `4409`，reason 为
“字幕模式未激活”。`subtitles → meeting` 可保持连接，`meeting → idle` 会撤销连接。

`/ws/v1/control` 与 `/ws/assistant/cmd` 都持续广播完整 `runtime_state`。命令 ack 只回请求连接，广播发给
全部控制连接，两者没有固定先后顺序；前端必须按 `request_id`/`event` 分类，并以最高
`runtime_revision` 对账 `mode/pcm_owner/active_meeting_id`。命令一旦被服务端接受，即使请求连接断开也
继续执行；其他连接可从广播收敛，命令超时或重连可通过 `GET /api/runtime` 对账。

会议事件通道断线重连先消费 `meeting_snapshot`，收到 `resync_required` 或 revision 跳变时通过
`GET /api/v1/meetings/{id}/transcript` 重建基线。前端状态和浏览器存储都不是事实源。

`minutes_state_changed/completed` 会携带刚落库的完整 `minutes` 对象，前端可直接渲染；若事件因
慢客户端丢失，仍以 HTTP 读取为恢复路径。前端团队还必须在 `meeting_snapshot.meeting.id` 变化时
清空上一场会议的 segments、speakers、minutes、gaps，并在异步 transcript 回写前校验目标会议 ID，
避免旧请求覆盖新会议状态。

## 6. 结束、故障与恢复

结束会议会先阻断新 PCM，再发送空 PCM 作为 EOF，并等待 WhisperLiveKit `ready_to_stop`。成功或超时后
都封存当前 confirmed 文本；超时会议标为 `interrupted/finalization_timeout`。纪要任务使用数据库
claim/lease，应用重启后可继续处理。会议期间浏览器关闭不会释放采集租约；应用关闭时活动会议标为
interrupted。所有结束路径都进入 `idle/none`，不恢复之前的 workload。

## 7. 服务健康与原始诊断

`GET /api/services` 继续保留每个外部服务的 HTTP `status`。WLK 项新增 additive 字段
`workload`、`ws_state`、`reconnect_count`、`last_event_age_ms`；HTTP status 与 workload/ws_state
彼此独立。长时间静音只会增加事件年龄，不足以判定 degraded。

顶层 `diagnostics` 固定有 `audio_hub`、`interaction`、`subtitles`、`tts`、`last_transition` 五个键。
AudioHub sink 满时丢弃最老 PCM、保留最新 PCM；interaction queue 满时保留已排队块、拒绝新块。
TTS 记录 `first_chunk_ms`、`chunk_count`、`max_source_chunk_gap_ms`、
`median_source_chunk_gap_ms`、`source_chunk_gaps_over_200ms` 等源块原始诊断。系统不读取 WLK 日志，
不扫描游戏或其他进程，也不做自动资源归因。

## 8. 自动化验证与真实验收

以下自动化命令是发布门禁，不表示本文档更新时已经重新执行：

```bash
VR_TEST_DATABASE_URL=postgresql:///knowledge uv run pytest tests/
uv run mypy src/
uv run ruff check src/ tests/
cd ui && npm test -- --run
cd ui && npm run build
```

PostgreSQL 集成测试只使用随机临时 schema，并在 fixture 结束时 `DROP SCHEMA ... CASCADE`；不得把
测试 DSN 指向远程或生产数据库。

localhost 与 LAN 真实闭环仍须在发布前执行并回填；可列预期结果，但不得把待测场景写成已通过：

```bash
# localhost 轮次
scripts/run-all.sh
curl --fail --silent http://127.0.0.1:8100/api/runtime | python3 -m json.tool
curl --fail --silent http://127.0.0.1:8100/api/services | python3 -m json.tool

# 停止上一轮全部子进程后，执行 LAN 轮次
VR_BIND_HOST=lan scripts/run-all.sh
# 在同一台笔记本上，将示例地址替换为 run-all.sh 输出的实际 LAN IP
VR_LAN_IP=192.0.2.10
curl --fail --silent "http://${VR_LAN_IP}:8100/api/runtime" | python3 -m json.tool
curl --fail --silent "http://${VR_LAN_IP}:8100/api/services" | python3 -m json.tool
```

两轮都应覆盖：`assistant → meeting → idle`、`subtitles → meeting → idle`、双浏览器相反命令、WLK
未 ready、活动字幕断线重连、prepared meeting abort，以及外部高负载下只观察原始诊断。预期稳定态
只有一个 PCM owner，两个浏览器收敛到相同最高 revision；meeting `recording` 晚于模式 commit；会议
结束后 `/ws/subtitles` 收到 `4409`；PostgreSQL 和 runtime 目录都没有音频，interrupted 记录仍存在。
每轮只记录执行时间、revision、mode、owner 和诊断计数，不记录音频或完整转写。LAN 轮次在同一台
笔记本使用 `run-all.sh` 输出的实际 LAN IP 访问 `8100`，不可用 localhost 代替；若未来有第二设备，
可作为可选扩展验证，但不是发布门禁。

## 9. 发布与回退

- 前端、后端、控制协议和字幕 WS 资格规则必须同版整体发布、整体回退，禁止只切换其中一层。
- 发布前记录完整前后端 commit SHA。本变更没有数据库 migration、模型 ID 或端口变化；
  `/api/services` 新字段是 additive，旧客户端可忽略。
- 回退时先停止 `run-all.sh` 及全部子进程，再将整个工作树切回发布前 SHA；用同一 SHA 同步后端依赖、
  构建前端并重新启动：

  ```bash
  RELEASE_BEFORE_SHA=0123456789abcdef0123456789abcdef01234567
  git switch --detach "$RELEASE_BEFORE_SHA"
  uv sync --all-extras
  cd ui && npm ci && npm run build && cd ..
  scripts/run-all.sh
  ```

  示例 SHA 必须替换为发布前记录值；启动后验证 assistant 基础链路，不得混用新旧前后端。
- 停机可能把进行中的会议标为 `interrupted`；prepared abort 的
  `interrupted/mode_switch_aborted` 也是审计事实。回退不得删除 meeting record、confirmed 转录、
  recovery journal 或纪要数据。旧版不会提供新 owner/诊断字段，已打开页面需刷新重连。
