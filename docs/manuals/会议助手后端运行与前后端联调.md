# 会议助手后端运行与前后端联调手册

本文是会议助手 V1 的运行手册。架构决策见
[`../superpowers/specs/2026-08-21-meeting-assistant-design.md`](../superpowers/specs/2026-08-21-meeting-assistant-design.md) 与
[`../decisions/0007-bounded-meeting-summary-generation.md`](../decisions/0007-bounded-meeting-summary-generation.md)，前后端共同契约见
[`../../contracts/meeting-assistant/v1/`](../../contracts/meeting-assistant/v1/)。

## 1. 数据边界

- PostgreSQL 是会议、confirmed 转录、匿名 speaker 映射与 AI 纪要的事实源。
- 不保存音频；会议采集也不写 `runtime/subtitles/current.srt`。
- `runtime/meetings/recovery/*.jsonl` 只在 PostgreSQL 短暂写失败时保存 confirmed 文本操作，
  目录权限 `0700`、文件权限 `0600`，成功回放后删除。
- partial 只通过 WebSocket 展示，崩溃时允许丢失。

## 2. PostgreSQL 一次性准备

以 `knowledge` 库管理员执行：

```bash
psql knowledge -f scripts/bootstrap-meeting-db.sql
```

脚本等价于以下一次性授权：

```sql
CREATE ROLE sona_app LOGIN;
CREATE SCHEMA sona AUTHORIZATION sona_app;
REVOKE ALL ON SCHEMA sona FROM PUBLIC;
GRANT CONNECT ON DATABASE knowledge TO sona_app;
GRANT USAGE, CREATE ON SCHEMA sona TO sona_app;
```

运行时角色不需要创建数据库、角色或访问其他 schema。V1 migration 只新增对象；应用回退时旧版本
忽略该 schema。备份和恢复沿用 `knowledge` 库的现有 `pg_dump`/`pg_restore` 流程。

## 3. 配置与启动

```bash
export SONA_MEETING_DATABASE_URL='postgresql://sona_app@/knowledge'
export SONA_MEETING_SCHEMA='sona'
export SONA_MEETING_SUMMARY_MODEL='qwen/qwen3.6-35b-a3b'
export SONA_MEETING_SUMMARY_REASONING='off'
# 流式连接连续 60 秒无数据才判定 read timeout
export SONA_MEETING_SUMMARY_TIMEOUT_SECS='60'
# 单次 map/reduce/repair 调用与整条任务的 wall-clock deadline
export SONA_MEETING_SUMMARY_REQUEST_TIMEOUT_SECS='180'
export SONA_MEETING_SUMMARY_JOB_TIMEOUT_SECS='600'
# 生成和客户端双重上限
export SONA_MEETING_SUMMARY_MAP_MAX_OUTPUT_TOKENS='2048'
export SONA_MEETING_SUMMARY_REDUCE_MAX_OUTPUT_TOKENS='10240'
export SONA_MEETING_SUMMARY_TITLE_MAX_OUTPUT_TOKENS='128'
export SONA_MEETING_SUMMARY_MAX_OUTPUT_CHARS='65536'
# 长会议按约 2 万字符或 20 分钟切块
export SONA_MEETING_SUMMARY_MAX_INPUT_CHARS='20000'
export SONA_MEETING_SUMMARY_CHUNK_MAX_DURATION_MS='1200000'
# SpeechRail OpenAI Realtime `/v1/realtime` 连接；API key 仅在 SpeechRail 开启认证时设置
export SONA_SUBTITLE_SPEECHRAIL_URL='ws://127.0.0.1:8201/v1/realtime'
export SONA_SUBTITLE_SPEECHRAIL_API_KEY=''
# SpeechRail 的 transcription/diarization profile 负责 ASR/分人；本项目不下载或启动模型
uv run sona-ui
```

SpeechRail 的 `speechrail/qwen3-asr-1.7b` 与 diarization profile 必须由独立 SpeechRail 服务预先配置；
默认禁止隐式下载。模型路径、profile、worker 和健康状态由 SpeechRail 管理，`sona` 不读取或复制
这些绝对路径。`scripts/run-all.sh` 只启动 `sona-ui`，SpeechRail 必须单独启动并先验证 `8201` 就绪。
`sona-ui` 启动时在 advisory lock 下执行
migration、回放 journal、将崩溃遗留的 `recording/finalizing` 标为 `interrupted`，再启动纪要 worker。
初始化失败会记录脱敏错误类型，普通助手继续运行；会议 HTTP API 返回 `storage_unavailable`。

纪要固定走 LM Studio 原生 `/api/v1/chat` 并关闭 reasoning。模型输入使用 `S0001` 短证据编号，
应用在校验边界映射回真实 segment UUID；map、reduce、repair 各自有 token 上限，客户端另有字符上限。
`summary_timeout_secs` 仅表示流式读取空闲超时，单次调用和整条任务分别由 request/job deadline 控制。
当前 prompt 版本为 `v4-map-domain-10240`。最终 reduce/repair 的模型侧契约限制为最多 8 个主题、8 个决策、
8 个行动项、4 个风险、4 个开放问题和 6 个亮点，并限制单项长度；分块 map 是中间结果，集合上限使用
领域模型容量（主题/决策/行动项/亮点最多 12 个，风险/开放问题最多 8 个），避免在归并前丢弃一个分块内的
独立事实。模型调用统计显示输出 token 触顶且 JSON 不完整时直接归类为 `output_limit`，不再误报为普通
`invalid_schema` 或继续重复 repair。

### 3.1 长会议 Map/Reduce 生成流程

Map/Reduce 的作用是把“长输入的上下文边界”和“最终纪要的紧凑输出边界”解耦：map 在每个分块内尽量保留
独立事实，reduce 再做跨分块去重、归并和全局概览。当前 worker 按分块顺序执行 map；它首先解决的是上下文
隔离、证据可追溯和输出有界问题，不以并行加速为目标。

```text
已封存 confirmed segments
          │
          ├─ 未超过阈值 ─► 单次 MAP（map 契约） ─► 解析短引用/校验证据 ─► 落库
          │
          └─ 超过阈值
              │
              ▼
        按 segment 边界切块
        字符达到 20,000 或时间达到 20 分钟即切分；相邻块重叠 1 个 segment
              │
       ┌──────┼────────┐
       ▼      ▼        ▼
     MAP-1  MAP-2     MAP-N  （每块独立编号 S0001…）
       │      │        │
       └──────┴────────┘
              │
      应用把每块短引用解析为真实 segment UUID
              │
              ▼
      仅把已验证的 map JSON 交给 REDUCE
              │
              ▼
    去重/归并/全局概览 ─► 最终契约 ─► evidence 校验 ─► Markdown + PostgreSQL
```

| 阶段 | 模型输入 | 主要作用 | 集合上限（topics / decisions / action_items / risks / open_questions / highlights） |
|---|---|---|---|
| MAP | 一个分块的 `[S0001]` 短引用转录 | 抽取本分块事实，保留独立议题、决策和行动项 | `12 / 12 / 12 / 8 / 8 / 12`；`2048` tokens |
| REDUCE | 已通过证据校验的 map JSON，不再发送全量转录 | 跨块去重、合并证据、生成全局概览 | `8 / 8 / 8 / 4 / 4 / 6`；`10240` tokens |
| REPAIR | 失败阶段的 JSON 草稿 | 只修复结构，不补充事实；每个失败阶段最多一次 | 使用对应阶段契约；不重新发送完整转录 |

每个分块的 `S0001` 编号只在该分块内有效。应用在 map 校验后立即把它解析为真实 segment UUID，reduce
只接收已解析、已验证的 JSON；最终落库前还会再次验证 evidence 属于本次会议。短会议虽然不经过 reduce，
仍使用 map 契约生成一次结果，再转换为最终 `MinutesResult`。

### 3.2 首次生成失败的定位

2026-08-27 最新会议的第一次纪要生成，原始响应本身是合法 JSON，但包含 9 个 `topics` 和 7 个
`highlights`。从响应使用 `S0001` 短引用及调用序列可定位为 map 中间结果；旧版却提前套用了最终 reduce/repair
契约（分别最多 8 个主题、6 个亮点），因此在进入 reduce 前以 `invalid_schema` 失败。证据引用解析、ASR
封存和 PostgreSQL 持久化均不是这次失败点。

当前 `v4-map-domain-10240` 已将两层契约分开：map 使用领域容量，reduce/repair 使用紧凑最终容量。排查新
故障时先查看脱敏的 `generation_stats[].stage`：map 的集合超限检查 map 契约，reduce 的集合超限检查最终契约；
只有输出 token 已触顶且 JSON 未闭合时才归类为 `output_limit`。

同一会议同时只保留一个 `queued/generating` 纪要任务；前端触发生成时必须发送 `Idempotency-Key`。
任务完成或失败时，`minutes_state_changed` 可附带脱敏的 `generation_stats`，只包含阶段、模型、耗时、
token 数、生成速度和 TTFT，不包含 prompt、转写或模型正文。稳定错误码含：

| 错误码 | 含义 | 建议处理 |
|---|---|---|
| `summary_timeout` | 单次调用或整条任务达到 wall-clock deadline | 检查 LM Studio 负载后重试，不要盲目增大 read timeout |
| `output_limit` | 模型输出超过 token/字符安全上限 | 检查是否出现重复退化；必要时调整 prompt 或独立评测阈值 |
| `invalid_schema` | 首次输出及一次定向 repair 后仍不符合 schema | 保留失败记录，检查模型输出与 prompt 版本 |
| `invalid_evidence` | 证据引用不属于本次转写 | 不落库伪证据，修正模型输出后重新生成 |
| `summary_unavailable` | LM Studio 连接或服务不可用 | 检查服务状态、模型队列与本机资源 |

手动改标题、AI 生成标题和纪要自动标题在 PostgreSQL 持久化成功后都会发布 durable
`meeting_title_updated`。前端收到后原子更新当前会议、活动会议和历史列表；断线恢复仍以
`meeting_snapshot`/HTTP 为准。AI 标题按钮只调用生成接口一次，不再追加第二次 PATCH。

SpeechRail 和 LM Studio 进程可以常驻预热。`SubtitleProxy.start()` 只初始化代理并保持
普通字幕 workload paused，不会自动建立普通字幕连接或接收 PCM。

## 4. 运行时仲裁与会议边界

`RuntimeModeCoordinator` 维护四种稳定模式，并与 PCM owner 固定对应：`assistant/assistant`、
`subtitles/subtitles`、`meeting/meeting`、`idle/none`。服务进程常驻不等于 workload 活跃；任意稳定
时刻只允许一个 owner，prepared target 也不接收 PCM。

进入会议采用两阶段顺序：先 `prepare_start()` 创建 meeting record 并准备无 PCM capture，目标 ready 后
进入 owner `none` 屏障，静默并 drain 来源，再同步 `commit_start()`，原子提交
`meeting/meeting/runtime_revision` 并广播，最后才发布 `recording` 事件。目标准备失败时来源不变；
屏障后的失败优先恢复来源，恢复也失败则全停到 `idle/none`。prepared meeting 被 abort 时必须保留
`interrupted/mode_switch_aborted` 记录，不得删除。

用户命令串行且不互相抢占。shutdown 是唯一可以取消在途转换的路径；它会 abort prepared target、
尽力停止全部 workload，并以一次稳定广播收敛到 `idle/none`。会议完成、异常中止或 EOF finalization
超时后也进入 `idle/none`，不会自动恢复普通字幕或语音助手。会议始终不写普通字幕 `current.srt`。

## 5. 独立前端联调

- HTTP 基址：`http://127.0.0.1:8100/api/v1`
- 运行时快照：`http://127.0.0.1:8100/api/runtime`
- 控制 WebSocket：`ws://127.0.0.1:8100/ws/v1/control`
- 助手控制兼容 WebSocket：`ws://127.0.0.1:8100/ws/assistant/cmd`
- 会议事件 WebSocket：`ws://127.0.0.1:8100/ws/v1/meetings`
- 只读字幕 WebSocket：`ws://127.0.0.1:8100/ws/subtitles`
- OpenAPI：`contracts/meeting-assistant/v1/openapi.json`
- AsyncAPI：`contracts/meeting-assistant/v1/asyncapi.yaml`
- JSON Schema 与 fixtures：`contracts/meeting-assistant/v1/schemas/`、`fixtures/`

允许的独立前端 Origin 由 `SONA_MEETING_ALLOWED_ORIGINS` 配置，必须是 loopback URL。命令必须携带
`request_id`；普通字幕由 `start_subtitles` 控制命令激活，连接 `/ws/subtitles` 本身不改变或抢占模式。
该只读通道仅在 `subtitles/meeting` 合法；非法建连或存续期失去资格时固定关闭 `4409`，reason 为
“字幕模式未激活”。`subtitles → meeting` 可保持连接，`meeting → idle` 会撤销连接。

`/ws/v1/control` 与 `/ws/assistant/cmd` 都持续广播完整 `runtime_state`。命令 ack 只回请求连接，广播发给
全部控制连接，两者没有固定先后顺序；前端必须按 `request_id`/`event` 分类，并以最高
`runtime_revision` 对账 `mode/pcm_owner/active_meeting_id`。命令一旦被服务端接受，即使请求连接断开也
继续执行；其他连接可从广播收敛，命令超时或重连可通过 `GET /api/runtime` 对账。

会议事件通道断线重连先消费 `meeting_snapshot`，收到 `resync_required` 或 revision 跳变时通过
`GET /api/v1/meetings/{id}/transcript` 重建基线。前端状态和浏览器存储都不是事实源。

`minutes_state_changed/completed` 会携带刚落库的完整 `minutes` 对象，前端可直接渲染；若事件因
慢客户端丢失，仍以 HTTP 读取为恢复路径。前端团队还必须在 `meeting_snapshot.meeting.id` 变化时
清空上一场会议的 segments、speakers、minutes、gaps，并在异步 transcript 回写前校验目标会议 ID，
避免旧请求覆盖新会议状态。

## 6. 结束、故障与恢复

结束会议会先阻断新 PCM，再通过 SpeechRail OpenAI Realtime `/v1/realtime` 发送 `input_audio_buffer.commit` 作为 EOF，并等待转写终态。成功或超时后
都封存当前 confirmed 文本；超时会议标为 `interrupted/finalization_timeout`。纪要任务使用数据库
claim/lease，应用重启后可继续处理。会议期间浏览器关闭不会释放采集租约；应用关闭时活动会议标为
interrupted。所有结束路径都进入 `idle/none`，不恢复之前的 workload。

## 7. 服务健康与原始诊断

`GET /api/services` 继续保留每个外部服务的 HTTP `status`。SpeechRail workload 项新增 additive 字段
`workload`、`ws_state`、`reconnect_count`、`last_event_age_ms`；HTTP status 与 workload/ws_state
彼此独立。长时间静音只会增加事件年龄，不足以判定 degraded。

顶层 `diagnostics` 固定有 `audio_hub`、`interaction`、`subtitles`、`tts`、`last_transition` 五个键。
AudioHub sink 满时丢弃最老 PCM、保留最新 PCM；interaction queue 满时保留已排队块、拒绝新块。
TTS 记录 `first_chunk_ms`、`chunk_count`、`max_source_chunk_gap_ms`、
`median_source_chunk_gap_ms`、`source_chunk_gaps_over_200ms` 等源块原始诊断。系统不读取 SpeechRail 日志，
不扫描游戏或其他进程，也不做自动资源归因。

## 8. 自动化验证与真实验收

以下自动化命令是发布门禁；历史发布候选分支的结果不能替代当前 SpeechRail 外部服务的真实音频验收：

```bash
SONA_TEST_DATABASE_URL=postgresql:///knowledge uv run pytest tests/
uv run mypy src/
uv run ruff check src/ tests/
cd ui && npm test -- --run
cd ui && npm run build
```

PostgreSQL 集成测试只使用随机临时 schema，并在 fixture 结束时 `DROP SCHEMA ... CASCADE`；不得把
测试 DSN 指向远程或生产数据库。

2026-08-26 的 localhost/LAN 两轮闭环属于 SpeechRail 迁移前历史记录；当前发布必须重新验证
SpeechRail worker、ASR/diarization profile、TTS session 与真实音频链路。复现命令如下：

```bash
# localhost 轮次
scripts/run-all.sh
curl --fail --silent http://127.0.0.1:8100/api/runtime | python3 -m json.tool
curl --fail --silent http://127.0.0.1:8100/api/services | python3 -m json.tool

# 停止上一轮全部子进程后，执行 LAN 轮次
SONA_BIND_HOST=lan scripts/run-all.sh
# 在同一台笔记本上，将示例地址替换为 run-all.sh 输出的实际 LAN IP
SONA_LAN_IP=192.0.2.10
curl --fail --silent "http://${SONA_LAN_IP}:8100/api/runtime" | python3 -m json.tool
curl --fail --silent "http://${SONA_LAN_IP}:8100/api/services" | python3 -m json.tool
```

两轮都应覆盖：`assistant → meeting → idle`、`subtitles → meeting → idle`、双浏览器相反命令、SpeechRail
未 ready、活动字幕断线重连、prepared meeting abort，以及外部高负载下只观察原始诊断。预期稳定态
只有一个 PCM owner，两个浏览器收敛到相同最高 revision；meeting `recording` 晚于模式 commit；会议
结束后 `/ws/subtitles` 收到 `4409`；PostgreSQL 和 runtime 目录都没有音频，interrupted 记录仍存在。
每轮只记录执行时间、revision、mode、owner 和诊断计数，不记录音频或完整转写。LAN 轮次在同一台
笔记本使用 `run-all.sh` 输出的实际 LAN IP 访问 `8100`，不可用 localhost 代替；若未来有第二设备，
可作为可选扩展验证，但不是发布门禁。

本次实测记录（不含音频和完整转写）：

| localhost | `127.0.0.1:8100` | 历史 WLK HTTP ready 且普通字幕 workload 初始为 paused；双控制连接从相同 revision 1 出发，依次收敛为 `subtitles/subtitles` revision 2、`assistant/assistant` revision 3、`meeting/meeting` revision 4、`idle/none` revision 5；非法建连和存量字幕连接撤销均为 `4409` | `first_chunk_ms=287.8`、`chunk_count=31`、`max_source_chunk_gap_ms=45.3`、`source_chunk_gaps_over_200ms=0` |
| LAN | `run-all.sh` 输出的当次 LAN IP `:8100` | UI HTML、CSP 和健康接口可由实际 LAN IP 访问；双控制连接状态一致；最终一轮 `assistant → subtitles → assistant` 为 revision `5 → 6 → 7`，撤销前允许 2 个在途字幕事件完成，随后稳定关闭 `4409` | `first_chunk_ms=271.5`、`chunk_count=67`、`max_source_chunk_gap_ms=44.7`、`source_chunk_gaps_over_200ms=0` |

输出帧链路正常，但不把 Agent 无法听觉确认的“扬声器实际音量”写成已人工听到。

同日故障演练中，停止旧 WLK 后 `start_subtitles` 与 `start_meeting` 都返回稳定失败，权威状态保持
`assistant/assistant@1`；prepared meeting 被 PostgreSQL 保留为
`interrupted/mode_switch_aborted`。活动字幕链从 `ready/connected` 进入 `degraded/backoff`，期间控制面
仍可用；旧 WLK 恢复后以 `reconnect_count=5` 回到 `ready/connected`。`subtitles → meeting` 保持既有只读
字幕连接，`meeting → idle` 再以 `4409` 撤销。两个控制客户端并发发送相反模式命令时依次观察到 revision
6、7，最终都收敛为 `assistant/assistant@7`。runtime 目录未发现音频制品；无 confirmed 文本的 epoch
按契约不生成 SRT 归档，有 confirmed 文本时的新旧 SRT 隔离由自动化测试覆盖。

## 9. 发布与回退

- 前端、后端、控制协议和字幕 WS 资格规则必须同版整体发布、整体回退，禁止只切换其中一层。
- 发布前记录完整前后端 commit SHA。本变更没有数据库 migration、模型 ID 或端口变化；
  `/api/services` 新字段是 additive，旧客户端可忽略。
- 2026-08-26 已用隔离的 detached worktree 检出发布前 `main`，在不切换当前功能分支的情况下执行旧版
  `test_runtime.py`、`test_control.py`、`test_ui_server.py`，结果通过；临时 worktree 随后已移除。该演练证明
  旧后端基础链可由同一依赖环境恢复，不替代发布时“前后端同一 SHA”整体回退要求。
- 回退时先停止 `run-all.sh` 及全部子进程，再将整个工作树切回发布前 SHA；用同一 SHA 同步后端依赖、
  构建前端并重新启动：

  ```bash
  RELEASE_BEFORE_SHA=0123456789abcdef0123456789abcdef01234567
  git switch --detach "$RELEASE_BEFORE_SHA"
  uv sync --all-extras
  cd ui && npm ci && npm run build && cd ..
  scripts/run-all.sh
  ```

  示例 SHA 必须替换为发布前记录值；启动后验证 assistant 基础链路，不得混用新旧前后端。
- 停机可能把进行中的会议标为 `interrupted`；prepared abort 的
  `interrupted/mode_switch_aborted` 也是审计事实。回退不得删除 meeting record、confirmed 转录、
  recovery journal 或纪要数据。旧版不会提供新 owner/诊断字段，已打开页面需刷新重连。
