# 物理输出音频采集验收手册

## 1. 当前交付边界

P1 交付设备绑定 Core Audio Tap Helper、16 kHz mono PCM 归一化、私有 UDS、Python
`PhysicalOutputSource`、`.app` 打包与测试入口。它能采集路由到当前所选物理输出端点的本机程序音频，
例如会议远端人声、浏览器媒体和系统提示音；不会自动包含麦克风近端人声。

2026-09-05 已增加功能开关后的字幕单源接线：字幕页可选择麦克风或电脑声音、读取输出设备、
启动与停止采集，并显示持续采集状态及断流错误。默认 `SONA_AUDIO_CAPTURE_ENABLED=false`，
设备门禁未完成前不默认启用或发布。会议仍使用既有麦克风输入；没有双源混音或数据库迁移。

本次实现先锁定用户选定的输出设备，不宣称自动跟随默认设备或热插拔恢复。切换设备需停止后重新选择。
下方 2026-08-31 的 P1 记录保留为历史验证记录；当前字幕接线的自动化与人工验收见第 7 节。

## 2. 隐私与安全须知

- 真实 capture 会覆盖目标物理输出设备上的所有本机播放音频，不局限于某个会议软件。
- 仅在无敏感会议、无通知隐私内容时执行人工测试；测试前关闭不相关音频应用。
- Helper 排除自身进程，字幕接线另排除 Sona 后端 PID，使用设备级 Tap；原始设备 UID 不进入
  IPC、日志或文档。一次性 capture token 仅用于本机 IPC 握手，不记录到日志或文档。
- PCM 只在内存和私有 UDS 中流动，不写数据库、日志、临时音频文件或 Bundle 资源。
- 人工脚本在内存中生成 440 Hz 测试音，结束后检查运行目录无 `.pcm`、`.wav`、socket 残留。

## 4. 内建默认输出 30 秒人工冒烟

### 4.1 前置条件

1. macOS 14.2+，将系统默认输出切换为“Mac 内建扬声器”。
2. 确认系统音量可听，关闭会议、聊天通知和其他敏感音频。
3. 完成 `.app` 构建与静态检查。
4. 预留约 30 秒；首次运行需在系统弹窗中主动允许系统音频录制。

### 4.2 显式执行

以下是命令行真实 capture 验收入口；确认参数用于防止自动化误触发。功能开关启用后的字幕页面
也能由用户点击开始发起采集：

```bash
uv run python scripts/smoke_audio_capture_helper.py \
  --duration 30 \
  --i-understand-this-will-request-system-audio-permission
```

脚本按 `prepare → 首帧 ready → commit → 内存测试音 → stop` 执行。若出现权限弹窗，应核对应用名和
用途说明后手动授权；拒绝时必须返回稳定错误并停止，不得降级为全局 Tap。

### 4.3 通过标准

最终结构化输出同时满足：

- `frames > 0`、`nonzero_frames > 0`、`peak_rms >= 0.005`；
- `first_sequence` 与 `last_sequence` 单调，`sequence_gaps = 0`；
- `residual_audio_or_socket_files = 0`；
- 系统声音仍从内建扬声器正常播放，Helper 停止后无持续录音指示；
- PostgreSQL、`runtime/subtitles/` 和会议恢复 journal 无新增采集音频。

权限拒绝、设备不可用、5 秒无 PCM、序列间隙或残留文件均判定失败。不要通过延长测试或关闭检查来
绕过失败，应先核验系统权限、默认输出设备和 Helper 签名是否变化。

## 5. 设备矩阵与长稳门禁

每个设备均重复“枚举 → 真实 capture → 非零电平 → stop → 无残留”，并记录设备类别而非原始 UID。

| 场景 | 最低验证 | 当前状态 |
|---|---|---|
| 内建扬声器 | 30 秒测试音、首授权与二次启动 | 待人工执行 |
| 3.5 mm / 有线耳机 | 30 秒测试音、插拔恢复 | 待具备设备后执行 |
| 蓝牙耳机/音箱 | 30 秒测试音、连接/断开恢复 | 待具备设备后执行 |
| USB 音频设备 | 30 秒测试音、格式转换与拔出恢复 | 待具备设备后执行 |
| HDMI / DisplayPort | 30 秒测试音、显示器休眠/恢复 | 待具备设备后执行 |
| 默认输出切换 | active 前后切换、generation/discontinuity 正确 | 待人工执行 |
| 2 小时长稳 | 无崩溃、无无界队列、无持续序列缺口 | 待人工执行 |

只有全部矩阵及 2 小时长稳通过，才可标记 `P1 device gate complete`。自动化全绿只能标记
`P1 code complete`。功能开关后的字幕接线可通过模拟来源进行开发回归；真实设备验收仍是默认启用、
发布以及进入会议持久化主路径的前置门禁。

## 6. 本机验证限制

2026-08-31 本机仅安装 Apple Command Line Tools，无完整 Xcode。已支持 SwiftPM、自测、手工
`.app` 组装与 ad-hoc `codesign`；未执行标准 XCTest、Developer ID、notarization、Xcode Archive，
也未代用户触发 TCC。上述项目必须保持“未验证”，不能由静态检查替代。

## 7. 电脑声音字幕（实验性接线，2026-09-05）

### 7.1 启用与页面操作

在 Sona 项目根目录完成 Helper 构建，并为新启动的应用进程设置开关和可执行文件路径：

```bash
scripts/build-audio-capture-helper.sh
SONA_AUDIO_CAPTURE_ENABLED=true \
SONA_AUDIO_CAPTURE_HELPER_EXECUTABLE=build/sona-audio-capture/sona-audio-capture.app/Contents/MacOS/sona-audio-capture-helper \
uv run sona-ui
```

若已有 Sona 服务运行，应先通过既有启停流程停止旧实例，避免端口与麦克风所有权冲突。
这些参数只启用入口；读取设备列表不创建 Tap。点击“开始字幕采集”且选择电脑声音时才请求系统音频权限。

1. 进入“实时字幕”；如果当前字幕正在运行，点击“停止字幕采集”。停止后页面会保留。
2. 将“音频来源”改为“电脑声音”，点击“刷新输出设备”，选择实际播放声音的设备。
3. 点击“开始字幕采集”，完成首次系统授权。采集所有路由到该设备的应用输出，不包含麦克风转写。
4. 确认页面显示“正在采集电脑声音”，播放内容后观察能量与 SpeechRail 字幕。
5. 点击“停止字幕采集”回收 Helper 与字幕租约。换设备需停止并重新选择；切回助手会释放输出采集。

来源断开或连续 5 秒没有 PCM 回调时，关闭该字幕流并显示错误；用户停止后可重试。
正常静音帧不触发此超时。页面的麦克风静音键不控制电脑声音，停止电脑声音需使用字幕停止按钮。
浏览器自身的音色试听未采用整浏览器进程排除，可能进入所选设备的采集范围。

### 7.2 控制契约

- `GET /api/audio/output-devices`：返回 `enabled` 与有界 `devices` 列表。仅暴露
  `device_ref`、`label`、`transport`、`is_default`；功能关闭时返回空列表，不启动 Helper。
- `start_subtitles` 新增可选 `capture`；省略时恢复本次应用运行期间上次选定的来源，首次默认麦克风。
- 显式麦克风配置：`{"source":"microphone"}`。
- 显式电脑声音配置：`{"source":"physical_output","device_ref":"<设备列表返回的引用>"}`。
- 活动字幕期间更改来源返回 `mode_conflict`，需要先停止；会议期间拒绝启动普通字幕。
- 权威快照新增 `subtitle_capture`、`output_capture_active`、`output_capture_error`；能力位为
  `capabilities.physical_output_enabled`。电脑声音启动命令的前端等待窗口为 60 秒，以覆盖授权及推理准备。
- 新增字段可选；v1 命令名、会议持久化接口和既有错误响应结构保持兼容。
