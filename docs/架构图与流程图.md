# voice-realtime 架构图与端到端流程图

> 更新：2026-08-21。当前权威拓扑为四个运行单元；会议助手是 `vr-ui` 内的互斥运行模式，
> `vr-interact` 是 `vr-ui` 的互斥替代入口。

## 1. 运行拓扑

```mermaid
flowchart TB
    MIC[麦克风<br/>16kHz mono int16]
    SPEAKER[扬声器<br/>24kHz]
    BROWSER[Voice Studio 浏览器]

    subgraph UI[vr-ui · 127.0.0.1:8100 · 默认交互所有者]
        HUB[AudioHub<br/>有界扇出 / 真静音]
        SESSION[InteractionSession<br/>单一生命周期]
        PIPE[Pipecat<br/>AudioInjector → Echo → STT → LLM → TTS]
        SUBPROXY[SubtitleProxy<br/>快照 / 重连 / SRT]
        CONTROL[严格控制协议<br/>握手 + request_id ack]
        MODE[RuntimeModeCoordinator<br/>assistant / meeting / idle]
        MEETING[MeetingSession<br/>窗口对账 / EOF 冲刷]
        SUMMARY[MeetingSummaryService<br/>证据 UUID / reasoning off]
        HUB --> PIPE
        PIPE --> SESSION
        HUB --> SUBPROXY
        MODE --> SESSION
        MODE --> MEETING
        MEETING --> SUBPROXY
    end

    subgraph SUB[vr-subtitles · 127.0.0.1:8001]
        WLK[WhisperLiveKit<br/>Qwen3-ASR 1.7B streaming · MPS/windowed<br/>--pcm-input]
    end

    subgraph BRIDGE[vr-bridge · 127.0.0.1:8765]
        TTS[Qwen3-TTS Bridge<br/>per-request voice<br/>24kHz]
    end

    LM[LM Studio · localhost:1234<br/>qwen/qwen3.6-35b-a3b]
    PG[(PostgreSQL knowledge<br/>voice_realtime schema)]
    SUMMARY_LM[LM Studio<br/>qwen/qwen3.8-27b]

    MIC --> HUB
    SUBPROXY <-->|PCM + full snapshot WS| WLK
    PIPE <-->|/api/v1/chat · reasoning off| LM
    PIPE <-->|/v1/audio/speech · PCM| TTS
    PIPE --> SPEAKER
    BROWSER <-->|assistant/subtitle WS| UI
    BROWSER <-->|command WS| CONTROL
    MEETING -->|confirmed text only| PG
    PG --> SUMMARY
    SUMMARY <-->|/api/v1/chat · reasoning off| SUMMARY_LM
    BROWSER <-->|/api/v1 + /ws/v1| MEETING
```

所有监听地址均为 loopback。默认离线运行；字幕模型目录缺失时 fail-fast，不隐式联网。

## 2. 交互模块

```mermaid
flowchart LR
    OWNER[InteractionOwnership<br/>flock 非阻塞] --> SESSION[InteractionSession]
    SESSION --> WORKER[PipelineWorker / WorkerRunner]
    WORKER --> IN[AudioInjector 或 LocalAudioTransport input]
    IN --> ECHO[EchoSuppressionProcessor]
    ECHO --> STT[FunASR SenseVoice<br/>本地 HF snapshot]
    STT --> FILTER[SelfEchoFilter]
    FILTER --> USER[LLMUserAggregator + Silero VAD]
    USER --> LLM[LmStudioNativeLLMService]
    LLM --> REC[BotTextRecorder]
    REC --> TTS[OpenAITTSService]
    TTS --> OBS[TTSStateObserver<br/>EchoState 唯一写者]
    OBS --> OUT[LocalAudioTransport output]
    OUT --> ASSIST[LLMAssistantAggregator]
```

UI 模式用 `AudioInjector`，headless 模式用本地 transport 输入。两种入口复用同一会话状态机；
停止顺序为 `runner.end()` → 限时等待 → 必要时取消 → 清空旧音频 → 释放所有权。

## 3. 交互时序

```mermaid
sequenceDiagram
    participant M as 麦克风/AudioHub
    participant P as Pipecat
    participant L as LM Studio
    participant T as TTS Bridge
    participant O as 扬声器/Observer

    M->>P: 16kHz PCM（512 frames≈32ms）
    P->>P: Echo/VAD/SenseVoice
    P->>L: POST /api/v1/chat<br/>reasoning="off"
    L-->>P: SSE message.delta
    P->>T: POST /v1/audio/speech<br/>voice 可按请求指定
    T-->>P: 24kHz PCM 真流式
    P->>O: TTSAudioRawFrame
    O->>O: 首块闭合 TTS TTFB
```

LM 原生 payload 不含 `role` 和 `max_tokens`。LLM 客户端在 stop/cancel/cleanup 时显式关闭。
TTS 模型访问由单并发门串行化，线程到 async 队列有界；WAV 仅用于需完整长度头的聚合响应。

## 4. 字幕时序

```mermaid
sequenceDiagram
    participant H as AudioHub
    participant P as SubtitleProxy
    participant W as WhisperLiveKit
    participant S as SRT
    participant B as Browser

    H->>P: 16kHz mono int16 PCM
    P->>W: WebSocket binary（服务端 --pcm-input）
    W-->>P: full snapshot<br/>lines + buffer_transcription
    P->>P: confirmed+partial 快照签名去重
    P->>S: confirmed 原子替换 current.srt
    P-->>B: 有界客户端队列广播完整快照
    W--xP: 断线
    P->>P: 清旧音频 + 可取消指数退避
    P->>W: 自动重连
    P->>P: 会议捕获释放后恢复普通 supervisor
```

稳定身份由时间、speaker 和文本共同构成；已有 confirmed 行不会遮蔽后续 partial。停止时把
`current.srt` 归档为带时间戳文件。

会议采集租约不依赖浏览器连接；会议模式不会写 `current.srt`，confirmed 文本只进入 PostgreSQL。
会议正常结束、中止或最终化超时后都会恢复普通字幕连接，应用 shutdown 时不恢复。

## 5. 会议助手时序

```mermaid
sequenceDiagram
    participant F as 独立前端
    participant R as UIRuntime/ModeCoordinator
    participant W as WhisperLiveKit
    participant P as PostgreSQL
    participant L as qwen3.8-27b

    F->>R: start_meeting(request_id, title)
    R->>R: 停止 Pipecat/LLM/TTS
    R->>P: 创建 recording 会议
    R->>W: 建立会议专属 PCM 会话
    W-->>R: partial + confirmed 全量窗口
    R-->>F: transcript_partial
    R->>P: 事务窗口对账 + revision
    R-->>F: transcript_reconciled
    F->>R: end_meeting(meeting_id)
    R->>W: 空 PCM EOF，等待 ready_to_stop
    R->>P: 封存转录 + queued minutes
    R-->>F: completed / minutes queued
    P->>L: 原生 /api/v1/chat，reasoning off
    L-->>P: 结构化纪要 + evidence segment UUID
    R-->>F: minutes completed
```

浏览器断开不停止会议；重连先取 `meeting_snapshot`，revision 不连续时再用 HTTP 拉完整转录。
PostgreSQL 暂不可写时禁止开始会议，但普通语音助手继续可用。恢复 journal 只保存权限为 `0600`
的 confirmed 文本操作，成功回放后删除。

## 6. 控制与状态时序

```mermaid
sequenceDiagram
    participant F as React
    participant C as /ws/assistant/cmd
    participant R as UIRuntime

    F->>C: WebSocket + 本机 Origin
    C-->>F: event=state（完整权威快照）
    F->>C: request_id + set_mic_muted(true)
    C->>R: 严格 Pydantic 解析后执行
    R->>R: AudioHub 静音 + 清交互队列
    R-->>C: 新 RuntimeStateSnapshot
    C-->>F: request_id + ok + 完整 state
    F->>F: 成功后才更新/持久化
```

控制失败只返回 `invalid_command`、`invalid_payload`、`command_failed` 或
`service_unavailable` 等稳定错误码，不返回内部异常文本。

## 7. 关键格式

| 链路 | 协议 | 格式 |
|---|---|---|
| AudioHub → Pipecat | `asyncio.Queue` | 16kHz / mono / int16 / 512 frames |
| SubtitleProxy → WLK | WebSocket binary | 同上，WLK `--pcm-input` |
| Pipecat → LM Studio | HTTP SSE | 原生 `/api/v1/chat`，`message.delta` |
| Pipecat → TTS Bridge | HTTP | `/v1/audio/speech`，`pcm` 或 `wav` |
| TTS Bridge → Pipecat | streaming body | 24kHz / mono / int16 PCM |
| WLK → SubtitleProxy | WebSocket JSON | full snapshot：confirmed `lines` + partial buffer |
| Browser → Control | WebSocket JSON | `request_id` + discriminated command |
| Browser ↔ Meeting | HTTP/WS V1 | `/api/v1/*` + `/ws/v1/{control,meetings}` |
| Meeting → PostgreSQL | psycopg async | 规范化文本、speaker、纪要；无音频列 |
