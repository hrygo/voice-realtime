## 1. 高阶架构图(总体视图)

> 三大进程 + 一个外部服务,单机离线闭环;链路编号见下图注。

```mermaid

    麦克风[🎤 麦克风 / 系统音频]

    subgraph MACHINE["🖥️ 单机 macOS · Apple Silicon · 全本地离线"]
        subgraph S1["📡 vr-subtitles · 端口 8001"]
            WLK[实时字幕服务<br/>WhisperLiveKit + Qwen3-ASR]
        end
        subgraph S2["🤖 vr-interact · 交互管道"]
            PIPE[语音交互管道<br/>Pipecat: STT→LLM→TTS 链路]
        end
        subgraph S3["🔊 vr-bridge · 端口 8765"]
            BRIDGE[TTS 桥<br/>OpenAI 兼容端点 + Qwen3-TTS]
        end
        LMSTUDIO[🧠 LM Studio · 端口 1234<br/>qwen/qwen3.6-35b-a3b]
    end

    麦克风 -->|"① 系统/麦克风音频 (WebSocket)"| WLK
    麦克风 -->|"① 16kHz PCM 分块"| PIPE
    WLK -->|"② 字幕事件 partial/confirmed"| 字幕消费
    PIPE -->|"③ POST /api/v1/chat · SSE"| LMSTUDIO
    LMSTUDIO -->|"③ answer 流 (message.delta)"| PIPE
    PIPE -->|"④ POST /v1/audio/speech"| BRIDGE
    BRIDGE -->|"④ 流式 WAV/PCM"| PIPE
    PIPE -->|"⑤ 24kHz 音频帧"| 扬声器
```

> **图 1 · 高阶架构说明(链路编号 ①–⑤)**
> 1. ① **音频输入分流** — 同一声源两路:系统/麦克风音频经 WebSocket 送字幕 ASR;16kHz PCM 分块送交互管道。
> 2. ② **字幕事件** — partial/confirmed 推送 Web UI / SRT / 事件桥。
> 3. ③ **LLM 对话** — 交互管道经 LM Studio 原生 `/api/v1/chat` 请求并流式接收回复(SSE,`reasoning=off`)。
> 4. ④ **TTS 往返** — 助手文本经 OpenAI 兼容 `POST /v1/audio/speech` 送 TTS 桥,流式 WAV/PCM 返回。
> 5. ⑤ **播放** — 24kHz 音频帧输出到扬声器。
>
> 全部进程与模型均在本机,无外网依赖。

## 3. 端到端详细流程图

### 3.1 交互链路(说话 → 转写 → LLM → TTS → 播放)

```mermaid
sequenceDiagram
    participant User as 👤 用户
    participant Mic as 🎤 LocalAudioTransport<br/>(16kHz PCM)
    participant VAD as 🔍 SileroVADAnalyzer<br/>(stop_secs=0.45s)
    participant STT as 🗣 FunASRSTTService<br/>(SenseVoice, CPU)
    participant UserAgg as 📝 LLMUserAggregator<br/>(SentenceAgg + VAD)
    participant LLMCtx as 📖 LLMContext<br/>(system + history)
    participant LLM as 🧠 LmStudioNativeLLMService<br/>(/api/v1/chat, reasoning:off)
    participant LMStudio as 🏠 LM Studio<br/>(localhost:1234)
    participant TTS as 🔊 OpenAITTSService<br/>(POST /v1/audio/speech)
    participant Bridge as 🌉 TTS Bridge<br/>(FastAPI :8765)
    participant Engine as ⚙️ TTSEngine<br/>(mlx-audio Qwen3-TTS)
    participant Spk as 🔈 LocalAudioTransport<br/>(24kHz 输出)
    participant AssistAgg as 📝 LLMAssistantAggregator

    User->>Mic: 说话 (语音输入)
    Mic->>VAD: 音频流 (16kHz PCM)
    VAD-->>Mic: 语音活动检测

    loop 流式 STT (逐句)
        Mic->>STT: 音频分块
        STT->>STT: SenseVoice 推理 (CPU)
        STT-->>UserAgg: partial 转写 (中间结果)
    end

    VAD->>UserAgg: 检测到静音 >0.45s (端点)
    UserAgg->>LLMCtx: 组装 user 消息
    UserAgg->>LLMCtx: + system prompt
    LLMCtx-->>UserAgg: 完整上下文

    UserAgg->>LLM: LLMUserMessageFrame
    LLM->>LLMCtx: 读取上下文 (adapter)
    LLM->>LLMCtx: 提取 messages → input items
    LLM->>LMStudio: POST /api/v1/chat<br/>input: text items<br/>reasoning=off, stream:true
    
    activate LMStudio
    LMStudio->>LMStudio: Qwen3-35B-A3B 推理<br/>(reasoning_output_tokens=0)
    LMStudio-->>LLM: SSE events (message.delta)
    deactivate LMStudio

    loop 流式 LLM 输出
        LMStudio->>LLM: message.delta (token by token)
        LLM->>LLM: 转 OpenAI Chunk<br/>(SimpleNamespace)
        LLM-->>TTS: LLMTextFrame (流式)
    end

    TTS->>Bridge: POST /v1/audio/speech<br/>model + input + fmt:wav
    activate Bridge
    Bridge->>Engine: stream_speech(text)
    Engine->>Engine: mlx-audio generate<br/>(stream=True, chunk=100ms)
    
    loop 流式 TTS 合成
        Engine->>Engine: float32 → int16 PCM
        Engine-->>Bridge: PCM 字节块 (AsyncIterator)
    end

    Bridge->>Bridge: 组装 WAV 头 (44 bytes)
    Bridge-->>TTS: StreamingResponse (audio/wav)
    deactivate Bridge

    TTS->>Spk: 音频帧 (24kHz)
    Spk->>Spk: 扬声器播放

    Spk->>AssistAgg: assistant 消息回写
    AssistAgg->>LLMCtx: 追加 assistant 到历史
    LLMCtx-->>AssistAgg: 更新上下文

    Note over User,LLMCtx: 下一轮循环 (等待用户说话)
```

> **图 3 · 交互链路流程说明(步骤编号 ①–⑧)**
> 1. ① **采集** — 用户说话,麦克风采集 16kHz PCM。
> 2. ② **VAD** — Silero 持续检测语音活动。
> 3. ③ **STT** — SenseVoice 流式转写,产出 partial 中间结果。
> 4. ④ **端点与上下文** — 静音 >0.45s 判定端点,聚合器组装 user 消息并入上下文。
> 5. ⑤ **LLM** — `LmStudioNativeLLMService` 走原生 `/api/v1/chat` 且 `reasoning=off`(OpenAI 兼容端点忽略该参数),SSE `message.delta` 流式接收。
> 6. ⑥ **TTS 请求** — OpenAITTSService 流式请求 TTS 桥。
> 7. ⑦ **合成与播放** — TTSEngine 按 100ms 分块合成 int16 PCM(24kHz),桥拼接 44 字节 WAV 头后返回,扬声器播放。
> 8. ⑧ **上下文回写** — 末尾 assistant 聚合器把回复写回 `LLMContext`,支撑多轮对话。

### 3.2 字幕链路(音频 → WhisperLiveKit → 事件消费)

```mermaid
sequenceDiagram
    participant Mic as 🎤 音频输入
    participant WLK as 📡 WhisperLiveKit<br/>(:8001, qwen3-streaming)
    participant Q3ASR as 🧠 Qwen3-ASR-1.7B<br/>(MPS 原生流式)
    participant WS as 📡 WS /asr<br/>(mode=full)
    participant Stream as 📥 SubtitleStream
    participant Parser as 🔧 parse_event()
    participant Tracker as 🗂 SubtitleEventTracker
    participant Consumer as 👁 消费者<br/>(SRT/Web UI/日志)

    Mic->>WLK: 音频流 (系统/麦)
    WLK->>Q3ASR: 音频分块 (2s 滚动窗口)
    Q3ASR-->>WLK: incremental decode<br/>(stable_text, partial)

    loop 流式 ASR 处理
        Q3ASR->>Q3ASR: KV-cache 增量解码
        Q3ASR-->>WLK: buffer_transcription (partial)
        Q3ASR->>Q3ASR: finalization_mode=accuracy
        Q3ASR-->>WLK: confirmed lines<br/>(start, end, speaker, text)
    end

    WLK->>WS: JSON 事件推送<br/>type + buffer_transcription + lines
    WS->>Stream: WebSocket message
    Stream->>Parser: json_loads → payload
    Parser->>Parser: 判断 msg_type

    alt type=config
        Parser-->>Stream: SubtitleEvent(kind=config)
    else type=error
        Parser-->>Stream: SubtitleEvent(kind=error)
    else 含 buffer_transcription
        Parser->>Parser: 提取 confirmed lines<br/>(speaker ≠ -2)
        alt 有 confirmed
            Parser-->>Stream: SubtitleEvent(kind=confirmed)<br/>(text, start, end, speaker)
        else 仅 partial
            Parser-->>Stream: SubtitleEvent(kind=partial)<br/>(text)
        end
    end

    Stream->>Tracker: track(event)
    Tracker->>Tracker: confirmed: 检查 (start, text) 去重
    Tracker->>Tracker: partial: 比较 last_partial
    Tracker-->>Consumer: 新事件 (True)

    Consumer->>Consumer: partial → 浅色行可修正<br/>confirmed → 追加定稿<br/>带时间戳/说话人/翻译
```

> **图 4 · 字幕链路流程说明(步骤编号 ①–⑤)**
> 1. ① **音频上报** — 音频流经 WebSocket 推送给 WhisperLiveKit。
> 2. ② **ASR 解码** — Qwen3-ASR 增量解码(2s 滚动窗口),周期性产出整份 FrontData 快照。
> 3. ③ **事件解析** — `parse_event` 按类型归一化:partial 取自 `buffer_transcription`(浅色、可修正),confirmed 取 `lines` 中最后一个定稿段(带 start/end/speaker),另有 config / error / ready_to_stop。
> 4. ④ **去重** — `SubtitleEventTracker` 以「confirmed:(start, text) 元组」与「partial:当前文本」双重去重。
> 5. ⑤ **消费** — 只对外发出新事件,渲染为 Web UI / SRT / 日志。

## 4. 关键数据流速查

| 连接 | 协议 | 方向 | 数据格式 |
|---|---|---|---|
| 麦克风 → Pipecat | LocalAudioTransport | 输入 | 16kHz PCM |
| Pipecat → 扬声器 | LocalAudioTransport | 输出 | 24kHz PCM |
| LLMService → LM Studio | HTTP POST `/api/v1/chat` | 请求 | JSON: `{model, input, reasoning, stream}` |
| LM Studio → LLMService | SSE | 响应 | `data: {"type":"message.delta","content":"..."}` |
| TTSService → TTS Bridge | HTTP POST `/v1/audio/speech` | 请求 | JSON: `{model, input, response_format, voice, speed}` |
| TTS Bridge → TTSService | HTTP StreamingResponse | 响应 | `audio/wav` (PCM int16 + 44B WAV header) |
| WhisperLiveKit → 事件 | WebSocket `/asr` | 双向 | JSON: `{type, buffer_transcription, lines}` |
